# PROMPT: интернет-магазин «Тандыр Сетка»

Этот файл — полная спецификация проекта. Его можно скопировать целиком и
отдать AI-ассистенту (или разработчику) как техническое задание — чтобы
воссоздать сайт с нуля или продолжить доработку в том же стиле и той же
структуре.

---

## 1. Бизнес-контекст

Интернет-магазин по продаже аксессуаров для тандыра (сетки, гаки, насадки,
сковороды, чехлы) собственного производства. Доставка по всей Украине
(Новая почта). Оплата согласовывается индивидуально (прямой интеграции
эквайринга пока нет).

## 2. Технические ограничения (обязательно)

- **Только чистый HTML/CSS/JavaScript.** Никаких фреймворков (React, Vue и
  т.п.), никаких сборщиков (Webpack, Vite), никакого npm/node_modules.
  Код должен открываться и работать без этапа сборки.
- **JSON как локальная база данных.** Все товары и настройки хранятся в
  JSON-файлах (`data/products.json`, `data/config.json`), а не зашиты в
  коде. Не-программист должен уметь добавить товар, просто отредактировав
  JSON.
- Код должен работать при простом статическом хостинге (загрузил файлы —
  и сайт работает), без бэкенда/сервера приложений.
- Совместимость: современные браузеры (Chrome, Safari, Firefox последних
  версий), мобильные устройства в первую очередь (сайт должен быть
  полностью адаптивным).

## 3. Структура файлов (обязательна именно такая раскладка)

```
tandyr-shop/
├── index.html
├── css/style.css
├── js/main.js
├── data/products.json
├── data/config.json
├── img/                      (фото товаров, имя = поле "image" в products.json)
├── robots.txt
├── sitemap.xml
└── google-sheets-webhook.gs
```

Обоснование: разделение данных/логики/разметки/стилей позволяет владельцу
бизнеса (не программисту) редактировать товары и цены самостоятельно, а
разработчику — быстро находить нужный код.

## 4. Дизайн-система

Направление: **минимализм в стиле Apple.**

### Цвета (CSS custom properties, светлая + тёмная тема через
`prefers-color-scheme` и атрибут `data-theme`)

| Токен | Светлая | Тёмная |
|---|---|---|
| `--bg` | `#ffffff` | `#000000` |
| `--bg-secondary` | `#f5f5f7` | `#1c1c1e` |
| `--text` | `#1d1d1f` | `#f5f5f7` |
| `--text-secondary` | `#6e6e73` | `#98989d` |
| `--accent` | `#d2560c` (угольно-оранжевый) | `#ff6b35` |
| `--line` | `#d2d2d7` | `#38383a` |
| `--danger` | `#c0392b` | `#c0392b` |

Радиусы: `--radius-s: 10px`, `--radius-m: 16px`, `--radius-l: 24px`.
Кнопки — полностью скруглённые (`border-radius: 980px`, приём из
Apple-дизайна).

### Типографика

Системный шрифтовой стек (без загрузки внешних шрифтов):
`-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", Roboto,
Helvetica, Arial, sans-serif`.

Крупные заголовки — большой размер, отрицательный трекинг (`letter-spacing:
-0.02em … -0.04em`), плотный `line-height`. Один шрифт, разная толщина
(400/500/600/700) — без декоративных шрифтов.

### Layout

- Sticky-навигация с блюром фона (`backdrop-filter: blur(20px)`)
- Крупный hero-блок с анимированной SVG-иллюстрацией (медленное вращение,
  единственный акцентный момент анимации на сайте)
- Карточки на нейтральном сером фоне (`--bg-secondary`), крупные скругления
- Минимум декоративных элементов — фокус на тексте и цене

### Иконки/визуалы товаров

Реальных фото на старте нет. Вместо заглушек из интернета — **сгенерированные
inline-SVG иконки** по категории товара (кольца-сетка, крюк, конус, сковорода,
чехол, набор из 4 кружков). Как только появляется реальное фото
(`<img>` по пути из `image`), оно подгружается вместо иконки; при ошибке
загрузки (`onerror`) — автоматический откат на иконку. Никогда не
использовать случайные стоковые фото из интернета как заглушки.

## 5. Схема данных

### data/products.json — массив товаров

```json
[
  {
    "id": 1,
    "name": "Название товара",
    "description": "Описание (может включать важные примечания капсом)",
    "images": ["img/имя-файла-1.jpg", "img/имя-файла-2.jpg"],
    "category": "Название категории",
    "options": [
      { "diameter": "подпись варианта", "price": 600 }
    ]
  }
]
```

Важно: поле `diameter` внутри `options` — это **не всегда число в
сантиметрах**. Это просто подпись варианта: может быть диаметр ("21"),
описание комплектации ("+ сковорідка 30 см"), размер по ширине/высоте
("висота 90см. Ширина 90см") или условное название ("Звичайний",
"Великий"). UI должен одинаково хорошо работать с любым текстом в этом
поле — не завязываться на то, что это число или что это именно
сантиметры.

Категории **не хардкодятся в коде** — кнопки фильтра в каталоге
генерируются на лету из уникальных значений `category`, встречающихся в
`products.json`. Добавили новую категорию в товаре — кнопка фильтра
появилась сама.

### data/config.json — настройки магазина

```json
{
  "shopName": "строка",
  "currency": "строка (грн)",
  "phone": "+380...",
  "phoneDisplay": "человекочитаемый номер",
  "telegram": { "botToken": "...", "chatId": "..." },
  "sheets": { "webhookUrl": "", "secret": "..." },
  "seo": { "title": "...", "description": "...", "keywords": "..." }
}
```

## 6. Функциональность

### 6.1 Каталог
- Карточка товара: фото-карусель или иконка, название, короткое описание
  (2 строки, обрезка через `-webkit-line-clamp`), цена «от N грн»
  (минимальная среди вариантов), подсказка «Выбрать вариант →»
- Карточка — **не `<button>`, а `<div role="button" tabindex="0">`** с
  обработчиками `click` и `keydown` (Enter/Space). Так сделано специально:
  внутри карточки лежат стрелки/точки карусели, а вложенные `<button>`
  внутри `<button>` — невалидный HTML и ломает поведение
- Клик по карточке (кроме клика по стрелке/точке карусели —
  `e.stopPropagation()`) → открывает модальное окно с полной карточкой товара

### 6.2 Карточка товара (модалка)
- Крупная фото-карусель или иконка
- Полное описание
- Выбор варианта — сегментированные «таблетки» (pill buttons), а не
  выпадающий список — обновляют цену вживую при клике
- Кнопка «Добавить в корзину»
- После добавления — инлайн-подтверждение («Добавлено — …»), окно **не
  закрывается автоматически**, чтобы можно было сразу добавить другой
  вариант того же товара

### 6.1a Карусель фото товара
- Данные: `images` — **массив** путей к фото (не одна строка). Один
  элемент — просто статичное фото. Больше одного — появляются стрелки
  prev/next, точки-индикаторы и свайп по касанию (`touchstart`/`touchend`,
  порог 30px)
- Одна и та же функция сборки карусели используется и на карточке
  каталога, и в модальном окне товара — разный только размер через CSS-класс
  контейнера (`product-visual` / `pd-visual`)
- **Ленивая загрузка**: `<img>` первого (активного) слайда получает `src`
  сразу; у остальных слайдов путь лежит в `data-src` и переносится в `src`
  только в момент первого переключения на этот слайд — фото не грузятся
  впрок
- Если фото не загрузилось (`onerror`) — конкретный слайд заменяется на
  иконку категории, остальные слайды не затрагиваются
- Для компактной миниатюры в корзине карусель избыточна — там всегда
  показывается только первое фото (`images[0]`)

### 6.3 Поиск и фильтр
- Текстовое поле поиска — фильтрует по названию и описанию товара
  (регистронезависимо)
- Кнопки-категории (генерируются из данных, см. раздел 5) — работают
  одновременно с поиском (AND, а не OR)
- Если ничего не найдено — показывается заметное сообщение, а не пустая
  страница

### 6.4 Корзина
- Выезжающая панель (drawer) справа
- Список товаров с миниатюрой, названием, выбранным вариантом,
  количеством (+/−), ценой, кнопкой удаления
- Сохраняется между визитами через `localStorage` (с try/catch — сайт не
  должен падать, если localStorage недоступен)
- Итоговая сумма пересчитывается на лету

### 6.5 Оформление заказа
- Форма: имя, телефон, город/отделение Новой почты, комментарий
  (необязательно)
- Валидация на клиенте (имя ≥ 2 символов, телефон ≥ 9 цифр, город ≥ 3
  символов) — без серверной проверки, но с понятными подсказками об
  ошибке под каждым полем
- После успешной отправки: экран подтверждения с номером заказа,
  сохранение заказа в `localStorage`, отправка уведомлений (см. 6.6),
  очистка корзины

### 6.6 Уведомления о заказе (не блокируют оформление, если не сработали)
- **Telegram**: `fetch` на `https://api.telegram.org/bot<token>/sendMessage`
  с деталями заказа
- **Google Sheets**: `fetch` на URL веб-приложения Google Apps Script
  (см. `google-sheets-webhook.gs`) с секретным ключом в теле запроса для
  защиты от постороннего доступа
- Обе интеграции **опциональны и не ломают сайт**, если не настроены
  (пустой `webhookUrl`/`botToken` → тихо пропускаем отправку)
- Обе интеграции работают только при размещении на реальном домене — при
  просмотре через `file://` или в некоторых песочницах с ограничением
  сети внешние запросы блокируются; ошибка ловится через `.catch()` и не
  прерывает оформление заказа

### 6.7 FAQ
- Аккордеон на нативных `<details>/<summary>` (без JS — работает даже
  если скрипт не загрузился)
- Рядом — статическая (не сгенерированная через JS) разметка
  `schema.org/FAQPage` в `<script type="application/ld+json">` — для
  расширенных сниппетов в поиске Google

## 7. SEO-требования

- `<title>`, `<meta name="description">`, `<meta name="keywords">` с
  релевантными ключевыми словами
- Open Graph и Twitter Card теги для превью при шаринге
- `<link rel="canonical">` (плейсхолдер, требует замены на реальный домен)
- JSON-LD:
  - `ItemList` из `Product`/`Offer` для каждого товара и каждого варианта
    (генерируется JS-ом после загрузки `products.json`)
  - `Organization` с телефоном и `areaServed: "UA"`
  - `FAQPage` (статически в HTML, см. 6.7)
- **Ключевые товары продублированы как статичный HTML** (не через JS) —
  см. раздел 8. Это критично: поисковые роботы должны увидеть реальный
  текст товара, даже не выполняя JavaScript
- Отдельные `robots.txt` и `sitemap.xml` в корне проекта

## 8. Гибрид «статика + динамика» для индексации

Два флагманских товара (`id: 7` и `id: 8` — сетки 2х и 3х рівневі) вшиты
прямо в `index.html` как обычная HTML-разметка (не рендерятся через JS из
JSON). Остальные товары рендерятся динамически из `products.json`.
JS при инициализации:
1. Пропускает рендер карточки для id из списка `STATIC_CARD_IDS`
2. Навешивает обработчик клика на уже существующий в разметке элемент

Если меняются статичные товары — нужно поправить текст в двух местах
(HTML и JSON). Это осознанный компромисс ради индексации, не баг.

## 9. Безопасность (важно предупреждать заказчика)

- Токен Telegram-бота и вебхук Google Apps Script хранятся в открытом
  JSON-файле — видны в исходном коде сайта любому желающему. Это
  приемлемо для бота, который только шлёт уведомления о заказах (не
  хранит и не может слить ничего критичного), но заказчик должен об этом
  знать
- Секретный ключ (`sheets.secret`) — минимальная защита от случайных
  посторонних запросов к Google-скрипту, не полноценная авторизация

## 10. Чего сайт сознательно НЕ делает (и почему)

- **Не принимает оплату на сайте** — эквайринг (например plata by mono от
  monobank) не подключён, это отдельная работа с реальным договором
  эквайринга
- **Не имеет админ-панели** — управление товарами через прямое
  редактирование `products.json`, это осознанный выбор ради простоты
  (нет бэкенда — нет и рисков его взлома)
- **Не хранит заказы на сервере** — только `localStorage` браузера +
  внешние уведомления (Telegram/Sheets). Полноценная CRM — это следующий
  шаг развития, не часть текущего ТЗ

## 11. Возможные следующие шаги (не делать без отдельного запроса)

- Подключение оплаты (monobank plata by mono)
- Реальные фотографии товаров
- Аккаунты покупателей / история заказов
- Промокоды и скидки от объёма
- Google Merchant Center — выгрузка товарного фида
- Analytics (Google Analytics / Meta Pixel)
